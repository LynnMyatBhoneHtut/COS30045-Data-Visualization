Bind the data and draw the bars

selectAll("rect").data(data).join("rect") creates one rectangle per brand. Each bar's width is its raw count in pixels and its position comes from its index, so the chart only fits by luck: Samsung's 1,096 models almost fill the 1,200-wide canvas, and the bars use about half of its height.

Fit the chart with scales

A linear scale maps counts from 0–1,200 onto 0–400 units of width, and a band scale splits the 600-unit height into one band per brand with 20% padding. The canvas shrinks to 500 × 600 and the bars still fit, because their size now comes from the scales instead of raw pixels.

Key code · js/ex4-6.js 
const xScale = d3.scaleLinear()
    .domain([0, 1200])
    .range([0, 400]);

const yScale = d3.scaleBand()
    .domain(data.map(d => d.brand))
    .range([0, 600])
    .padding(0.2);

// ...inside the data join
    .attr("y", d => yScale(d.brand))
    .attr("width", d => xScale(d.count))
    .attr("height", yScale.bandwidth())

Group each bar with its labels

Each brand gets a <g> group translated to its band. Inside the group the bar starts at x = 100 to leave room for the brand name, which is right-aligned with text-anchor: end, and the count sits 5 units past the end of the bar.

The x range dropped from 400 to 340 so the label space, the longest bar and its count all fit inside 500 units.

Key code · js/ex4-7.js 
const barAndLabel = svg
    .selectAll("g")
    .data(data)
    .join("g")
        .attr("transform", d => `translate(0, ${yScale(d.brand)})`);

barAndLabel.append("rect")
    .attr("x", labelSpace)       // 100 units reserved for the brand name
    .attr("y", 0)                // the group already sets the row
    .attr("width", d => xScale(d.count))
    .attr("height", yScale.bandwidth());

barAndLabel.append("text")
    .text(d => d.brand)
    .attr("x", labelSpace - 10)
    .attr("text-anchor", "end");

Reading the progression

FAQ

In 4.5 a bar's width is its count in canvas units and its y position is its index × 32. That only works because the canvas (1,200 wide) happens to be wider than the biggest count (1,096), and the 25 bars stop at y = 788, about half way down the 1,600-unit canvas. Exercise 4.6 fixes both with scales.

A linear scale maps a continuous domain onto a continuous range: here, counts from 0 to 1,200 onto 0 to 400 units of width. A band scale divides a range into equal bands, one per category, and gives each band a start position and a bandwidth; padding(0.2) turns 20% of each step into a gap.

Each group is translated to its brand's band, so the bar and both labels inside it are drawn relative to that row. That is why the bar's y can be 0: the group has already moved it into place, and moving the group moves all three together.

In the original folders each exercise has a page to itself. Here five of them share one page, and each file declares svg (and, from 4.4 on, drawBarChart). Without separate scopes the second file would stop with "Identifier 'svg' has already been declared". Wrapping each file in a function keeps those names private; inside it, only the container and the colours changed.
